# MyStockLog 운영·코드 점검 — 2026-09-07

## 결론

계산 서비스의 기존 테스트는 통과했지만 Vercel 이전이 미완료다. 화면 수를 늘리기보다 인증 설정, 저장소 통합, 장애 상태 표시를 우선한다. 이번 변경은 코드 수정이며 운영 배포와 실데이터 이전을 완료했다는 의미는 아니다.

## 확인한 운영 상태

- 운영 Vercel /api/auth/session은 HTTP 200, configured=false, authenticated=false를 반환했다. 접근 코드 또는 세션 비밀값 설정이 필요하다. 비밀값은 점검 과정에서 읽거나 출력하지 않았다.
- 보유관리는 api/positions.ts에서 기존 Sites D1으로 중계한다.
- 전략노트 /api/strategy-notes, 알림 /api/alerts, 푸시 /api/push/config의 Vercel 구현이 없다.
- 백테스트 조회 API가 누락되어 있었다. 이번 변경에서 기존 Supabase 테이블을 읽는 인증 필수 API를 추가했다. 쓰기·마이그레이션은 하지 않는다.
- Mac mini 수집기의 실제 실행 여부, Supabase 데이터 건수, 로그인 후 운영 화면 전체는 이번 점검에서 검증하지 못했다.

## 수정

- 서버와 화면이 같은 미국 장 상태 함수를 사용하도록 통합. 조기폐장 당일 확정일 판단 및 ET 표시 수정.
- 부가 최신가/수집 상태 조회 실패 시 저장된 일봉 조회는 유지. 정상가 유지 및 지연/실패/IP 변경 상태 전달.
- 설정 상태 조회가 단일 종목 조회로 잘못 처리되던 문제 수정.
- 인증 코드 변경 시 기존 세션 무효화, 서명 비교 보강, 만료·변조 검증, 로그인 요청 크기 제한.
- 로그아웃 버튼, 첫 데이터 로딩 실패 안내, 로그인 카드 중앙 정렬, 모바일 안내문 줄바꿈.
- 실제 상태를 숨기고 항상 최신값 확인 완료라고 표시하던 CSS 제거.
- 미사용 구형 백테스트 트리 화면 제거. Git 이력으로 복구 가능.
- 미사용 변수/타입 정리. backtest/phase4_2.mjs는 미사용 변수만 제거했고 계산 및 저장 결과는 변경하지 않음.
- dist-vercel 및 .vercel을 린트 대상에서 제외.

## 검증

- 기존 102개 테스트 통과.
- 인증·데이터 API·조기폐장 회귀 검증 추가 후 110개 통과.
- typecheck 통과, lint 오류/경고 0, Vercel 클라이언트 빌드 통과, diff 공백 검사 통과.
- 로컬 로그인 화면을 브라우저에서 시각 확인. 로그인 후 PC/모바일 전체 동작 및 Vercel 서버 함수 실배포 검증은 미완료.
- 빌드 결과 JS 약 924KB, gzip 약 266KB. 500KB 청크 경고는 남아 있다. 클라이언트 빌드는 Vercel 서버 함수 배포 검증을 대신하지 않는다.

## 우선순위

1. Vercel Production APP_ACCESS_CODE / APP_SESSION_SECRET 설정 및 배포 확인. 추측하기 어려운 긴 접근 코드를 사용하고 로그인 요청에 배포 단위 시도 제한을 추가한다. 현재 300ms 지연은 분산 무차별 대입 방어가 아니다.
2. 보유관리·전략노트·알림을 Supabase로 이전. 기존 사용자와 기록 소유자를 매핑하고 건수/내용 검증 후 전환한다. 공유 접근 코드 자체는 사용자별 데이터 분리를 제공하지 않는다.
3. 이전 사이트의 접근 정책 확인. 새 Vercel의 인증은 기존 Sites URL을 보호하지 않는다. 완전 이전 전 D1과 이전 사이트를 삭제하지 않는다.
4. App.tsx의 화면/차트/백테스트 보고서를 컴포넌트로 분리하고 필요할 때 로딩해 모바일 초기 다운로드를 줄인다.
5. 백테스트 해석 중 하드코딩된 수치와 JSON 값의 표시 단위 추론을 명시적인 보고서 스키마로 교체한다. 기존 결과 자체를 다시 쓰지 않는다.
6. Mac mini 수집기 정상 실행, 갱신 요청 큐 처리, 종목별 최신가 시각, 오류 회복을 실제 운영에서 확인한다. 현재 전체 liveQuote 상태만으로는 개별 종목 누락까지 정확히 표현하지 못한다.
7. 장 캘린더의 비정기 휴장과 수집기 중복 캘린더를 별도 검증한다. 이번 수정은 기존 달력 재사용과 조기폐장 표시/확정일 보완이다.

## 배포 전제

인증 환경 변수와 Supabase 백테스트 테이블/이전 데이터 준비 여부를 확인한 뒤 GitHub 배포를 진행한다. 새 API가 빈 결과를 반환하면 이전 데이터가 존재하는지 확인해야 하며 임의 결과를 생성하지 않는다.
